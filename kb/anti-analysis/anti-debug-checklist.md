# 反调试排查清单

## 摘要

用于在样本一运行就退出、行为异常或调试视图不稳定时，快速判断是否遭遇反调试、反虚拟机或环境探测。

## 适用场景

- 保护类型：轻量反调试、自定义检查、CTF 反分析干扰。
- 文件类型：本地二进制、加载器、带自校验样本。
- 分析目标：确认“程序坏了”还是“程序在躲调试”。
- 不适用条件：纯静态题、源码题、无执行路径的附件。

## 识别信号

- 在正常运行和调试运行下行为差异明显。
- 断点命中后程序立即退出、卡死或进入噪声路径。
- 时间、异常、线程、句柄、窗口类名等环境因素影响执行结果。

## 判断依据

- 先做对照实验：无调试器、带调试器、不同虚拟环境、不同断点方式。
- 如果行为差异稳定复现，优先记录触发条件，再定位具体检测点。
- 反调试通常不是单一 API 检查，很多时候是“多个弱信号叠加触发”。

## 处理思路

1. 建立基线：记录样本在最干净环境下的正常行为。
2. 引入单一变量：只改变是否附加调试器、是否有断点、是否在虚拟机内。
3. 观察退出点、异常点、时间窗口和线程变化。
4. 将“检测点”和“响应动作”分开记录，避免只记 patch 结果。
5. 只有在确认检测逻辑后，才决定是规避、补环境还是最小 patch。

## 常见误区

- 一上来全局 NOP，后面无法判断到底绕过了什么。
- 把普通异常控制流误判成反调试。
- 忽略时间行为和多线程竞争，只盯单个 API。

## 失败信号与转向条件

- 在不同环境下没有稳定差异，说明问题可能是样本损坏或依赖缺失。
- patch 某个检测点后又触发新的退出路径，说明存在分层检查。
- 一直无法复现，需回头核验样本、参数、依赖文件和输入条件。

## 工具与脚本

- 工具：调试器、API 监视、时间与异常事件观察、环境对比记录。
- 现有脚本：无统一脚本，优先保存“环境差异矩阵”。
- 输出产物：触发条件、检测点地址、响应路径、最小规避策略。

## 记录规范

- 样本 hash：必须记录。
- 平台与位数：必须区分。
- 是否需要管理员权限：如涉及驱动、服务或权限探测需记录。
- 是否涉及驱动、服务或内核组件：单独标注。
